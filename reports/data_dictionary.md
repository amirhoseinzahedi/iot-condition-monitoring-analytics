# Data Dictionary

## 1. Overview

This project uses a synthetic IoT condition monitoring dataset designed to simulate an environmental monitoring system.

The dataset contains:

- 10 devices
- 5 locations
- 30 days
- 1-minute sampling frequency
- 5 sensor types
- 432,000 sensor measurements

The data is organized into raw sensor measurements, anomaly ground truth, and model detection results.

---

# 2. Raw Sensor Data

File:

`data/raw/iot_sensor_data.csv`

This dataset contains the simulated sensor measurements generated by the project.

| Column | Type | Description |
|---|---|---|
| `timestamp` | datetime | Timestamp of the sensor measurement |
| `device_id` | string | Unique identifier of the monitoring device |
| `location_id` | string | Identifier of the physical monitoring location |
| `temperature` | float | Temperature measurement |
| `humidity` | float | Relative humidity measurement |
| `co2` | float | Carbon dioxide concentration |
| `airspeed` | float | Airspeed measurement |
| `light` | float | Light intensity measurement |
| `x` | float | X coordinate of the device location |
| `y` | float | Y coordinate of the device location |
| `production_day` | integer | Simulated production day, ranging from 1 to 30 |

# 3. Ground Truth Anomalies

File:

`data/ground_truth/anomalies.csv`

This file contains the anomalies intentionally injected into the synthetic dataset.

| Column | Type | Description |
|---|---|---|
| `row_index` | integer | Reference to the corresponding row in the generated sensor dataset |
| `timestamp` | datetime | Timestamp associated with the anomaly |
| `device_id` | string | Device associated with the anomaly |
| `sensor` | string | Sensor affected by the anomaly |
| `anomaly_type` | string | Type of injected anomaly |

## Anomaly Types

| Anomaly Type | Description |
|---|---|
| `stuck` | Sensor value remains constant or nearly constant for an abnormal period |
| `missing` | Sensor measurement is missing |
| `drift` | Sensor value gradually deviates from its expected behavior |
| `impossible_value` | Sensor measurement violates a physically or operationally valid range |
| `spike` | Short-duration abnormal deviation from the normal signal |

The ground-truth file contains 1,690 anomaly records.

Some anomaly records refer to the same
`(timestamp, device_id, sensor)` evaluation point.

Therefore, the number of unique evaluation points is 1,689.

---

# 4. Detected Anomalies

File:

`data/processed/detected_anomalies.csv`

This file contains the anomalies detected by the final hybrid detector.

| Column | Type | Description |
|---|---|---|
| `timestamp` | datetime | Timestamp of the detected anomaly |
| `device_id` | string | Device associated with the detection |
| `location_id` | string | Location associated with the device |
| `sensor` | string | Sensor associated with the detection |
| `detection_reason` | string | Primary reason assigned to the detection |
| `is_detected` | boolean | Indicates that the anomaly was detected |

The final detector produced 914 detections.

Detected reasons include:

- `missing`
- `stuck`
- `spike`

No final detections were classified as:

- `drift`
- `impossible`

# 6. Power BI Data Model

The Power BI dashboard uses a dimensional model.

## Fact Tables

### Fact_Measurements

Contains the complete sensor measurement dataset.

Grain:

> One sensor measurement for one device at one timestamp.

### Fact_GroundTruth

Contains ground-truth anomaly records.

Grain:

> One ground-truth anomaly record for one sensor, device, and timestamp.

### Fact_Detections

Contains model-generated anomaly detections.

Grain:

> One detected anomaly for one sensor, device, and timestamp.

# 8. Evaluation Grain

Model evaluation is performed at:

`(timestamp, device_id, sensor)`

This is important because the raw ground-truth anomaly file contains 1,690 records, while only 1,689 unique evaluation points exist at this grain.

The confusion matrix therefore uses unique evaluation keys rather than raw anomaly-record counts.

---

# 9. Important Terminology

### Ground Truth

The anomalies intentionally injected into the synthetic dataset and treated as the reference labels for model evaluation.

### Detection

An anomaly identified by the final hybrid detector.

### Detection Reason

The primary reason assigned by the detection pipeline to an identified anomaly.

### Precision

The proportion of detected anomalies that are actually anomalous.

### Recall

The proportion of ground-truth anomaly points detected by the model.

### F1 Score

The harmonic mean of precision and recall.

### Evaluation Point

A unique `(timestamp, device_id, sensor)` combination used as the unit of model evaluation.
